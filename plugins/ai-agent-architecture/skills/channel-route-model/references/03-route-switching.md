# 03 模型切线路与独立参数

§1 切换：停放、载入、不复制 · §2 保存与切换共用一条规则 · §3 授权声明 vs 线路可用性 · §4 线路增删与改主线路 · §5 会话中跨线路 · §6 应当被测试钉住的性质

## 1. 切换：停放、载入、不复制

**线路参数集合**要有一份明确的清单（如：最大输出、温度、思考类目 / 强度 / 预算、结构化输出模式、仅某协议族才有的输出选项、实测时间与实测值）。切换只搬这份清单里的字段。
旧 → 新（2026-09-27）：清单里原有「思考方言」一项；方言已一次性迁成类目（02 §3），行与停放线路上都不再有这个字段，切换自然也不再搬它。

**把模型从线路 A 切到线路 B**（步骤）：
1. 若 B 就是当前线路：只把「当前线路」写成显式的 B，结束。
2. 把模型当前的线路参数（清单里每个字段）**停放**到 A 名下。
3. 取出 B 名下停放的参数；**B 从未配置过 → 空集合**。
4. 用这份参数**覆盖清单里的每一个字段**：B 里没有的字段被清空，而不是保留 A 的值。
5. 从停放区移除 B；「当前线路」写为 B。模型 id 不变。

要点：
- **没配过的线路是一片空白（「未设置 · 不发」），绝不从当前线路复制。** 思考类目按协议族定义：一个协议上的「强度 = 高」复制到另一协议是跨族字段，轻则被丢弃、重则被拒；温度、最大输出同理（有的协议开思考时温度必须固定，最大输出每次必发）。
- 第 4 步必须覆盖**全部**字段，否则 A 的值会漏进 B。
- 实测值也按线路停放；「测上限」这类操作测的是**当前线路**，结果写回当前线路。

## 2. 保存与切换共用一条规则

编辑界面里，「保存时写入哪些线路字段」与「切换时停放哪些字段」必须由**同一个过程**决定。两处各写一份，迟早按不同规则清字段——
例如保存时会清掉不适用于本协议族的字段，切换时却原样停放，下次切回来就带着一个本不该存在的值。

切换前先展示**差异**：思考 / 最大输出 / 结构化 / 温度 / 服务端工具 各一行「旧 → 新」，未配置的显示为「未设置 · 不发」，用户确认后再切。

## 3. 授权声明 vs 线路可用性

有一类字段**是用户的授权，不是线路参数**：服务端工具（联网搜索、网页抓取、代码解释器）、文档输入、视频输入。

- 授权保存在模型上，**切线路时不清**——切走再切回来不该重填。
- 能否实际发出**在使用时按线路判断**：查画像 (平台, 协议族, 模型)。
- 当前线路发不出时：开关保持开启，下方说明原因。区分两种说法：「本平台没有这个能力」与「平台有，但这个模型不支持」（按模型的闸门）。
- 凡是**对外承诺能力**的地方——某个辅助代理是否可用、列表上的能力标记、上下文与工具预算的估算——一律读「实际能发出的集合」，不读原始授权；
  估算与实际运行必须拿同一份渠道数据，否则两边对不上。
- 例外：会让模型**从选择器里消失**的身份型字段（如「仅用于翻译」「仅用于转写」）仍按当前线路清——留一个看不见的声明，代价是模型从所有选择器里消失。

界面上用矩阵表达：行 = 能力（授权开关），列 = 线路，格 = 可发出 / 发不出 / 未实测，当前线路列高亮。

## 4. 线路增删与改主线路

- **有模型正在使用的线路，以及渠道唯一的一条线路，不允许关闭。**
- 模型启用一条渠道提供、但自己没配过的线路：从空白开始。
- 删除某条线路的参数：只能删非当前线路的；当前的须先切走。
- **改主线路时先钉住跟随者**：没有显式选择线路的模型跟随主线路。改主线路前，先把这些模型的「当前线路」显式写为**旧主线路**——
  否则它们会带着按旧协议族设置的参数悄悄换协议。合并时搬迁的模型同理（04 篇）。
- 新建渠道：平台提供的线路默认全部启用；「自定义」平台只启用一条，用户验证一条加一条。

## 5. 会话中跨线路

跨轮携带的协议专属内容（思考块、某些协议要求回传的输出条目）按（模型, 协议族）标记。同一模型换了协议族，新协议读不到旧协议的携带物，
退化为与「换了一个模型」相同的处理。通常不需要新逻辑，但要有测试钉住：切线路后的下一轮不会把旧协议的携带物发出去。

## 6. 应当被测试钉住的性质

- 切到没配过的线路：全部线路参数为空，没有从旧线路漏过来的值
- 切走再切回：原线路的值原样恢复；模型 id 不变
- 线路不存在：展示侧退回主线路，请求侧报错
- 改主线路：未显式选线路的模型被钉在旧主线路
- 授权在发不出的线路上：保留、不发送、不计入「实际能发出的集合」
- 跨协议族：旧协议的携带物不出现在新协议的请求里
