# 知识吸收协议：新事实怎么进来、旧结论怎么改、什么时候过期

本库的价值在于「已验证」三个字。一条没有证据的事实混进来，比没有这条事实更糟——审查时会据此判错。仅在用户要求收录或修正知识库时执行写回；普通查询、接入开发和审查不自动修改本库。本篇规定：一条新事实（新平台、新模型、新结论）从哪进来、写到哪、怎么写、怎么推翻旧的、怎么过期，以及每次写回的自检清单。

两个原则贯穿全篇：

1. **事实只有一处正文，其余都是指针。** 正文按下表中的主题文件维护；能力与平台矩阵是结论表（[platform-matrix](platform-matrix.md) §0 与 §3 各节的「正文所在」行兼作目录），只写结论 + 指针。改事实 = 改正文一处 + 同步所有指向它的结论格。
2. **当前结论与历史分开。** 正文和矩阵保留当前结论；被推翻的判断移入 [结论历史](conclusion-history.md)，保留证据与当前条目链接。

## 1 一条事实的最小单元

写回的每条事实都要能拆成这七个字段，缺一个就还不是「事实」，是线索：

| 字段 | 例 | 缺了会怎样 |
| --- | --- | --- |
| **主键** (平台·渠道·线路, 面, 模型) | (New API · `[Pro]`, ②, gpt-5.6-sol) | 无法和别的行区分；中转站上同一 id 不同渠道结论相反 |
| **发了什么** 字段名与值 | `text.format:{type:"json_schema", strict:true, …}` | 后人无法复现 |
| **看到什么** 状态码 / 回显 / 回包字段 / 计费数字 | 200，回显 `{type:"text"}`，答案是合法 JSON 但不受 schema 约束 | 「支持 X」三个字审查时用不上 |
| **结论记号** ✅ ❌ 🔇 🔀 📄 | 🔇（收下不生效） | 静默 / 会响是审查优先级的依据 |
| **不这样会怎样** | 调用方拿到能解析的 JSON 却以为 schema 生效了 | 读者不知道严重程度 |
| **证据** 记法 + 日期 + 样本量 | 【实测 2026-09-24】4/4 | 无法判断证据是否需要复核 |
| **出处** 主题篇小节 | [structured-output](structured-output.md) §5.1 | 矩阵格子指不回正文 |

只有「发了什么 / 看到什么」两项能从日志里直接抄；其余五项是人判断的，写的时候要意识到这一点。

## 2 进来的四种入口

| 入口 | 典型场景 | 证据等级上限 | 进库前必须做的事 |
| --- | --- | --- | --- |
| **A 付费实测** | 拿到新 key，按 [errors-probing-observability](errors-probing-observability.md) §8 纪律打请求 | 【实测 YYYY-MM-DD】 | 记样本量；流式 / 非流式各测；中转站至少测两个渠道（[errors-probing-observability](errors-probing-observability.md) §8 第 7–11 条） |
| **B 审查项目时发现** | 审别人的代码，它在真实服务上这样写且能跑 | 【实现】 | 写清是哪个项目、哪条路径；判错前先实测（本篇证据等级） |
| **C 读文档 / 读中继源码** | 官方 API 参考页、New API 仓库 | 【文档 YYYY-MM】/【中继源码】 | 记页面日期；与已有实测冲突时并列记录，区分官方契约与观测范围 |
| **D 用户口述 / 对话中的说法** | 「我试过 X 在 Y 上不行」 | ⚠ | 只能进 [open-questions](open-questions.md)待核实表，不能进正文与矩阵 |

判断入口时别高估：从网关翻译层看到的回包，对官方只算「经 X 的实测」，且只有回包原样的面才能记成官方事实（[provider-layering](provider-layering.md) §9.5 透传证据清单）。请求侧被重新序列化的网关，「发 X 会不会 400」只对这台网关成立。

## 3 放到哪：决策树

按顺序问，第一个「是」就停：

| 内容 | 正文与索引 |
| --- | --- |
| 尚未核实、口述、推断 | [待核实项](open-questions.md) |
| 图片、视频、ASR | [媒体入口](../../ai-media-api-integration/SKILL.md) 中的对应正文与媒体矩阵 |
| 地址、鉴权、渠道变体 | [平台矩阵](platform-matrix.md) §3；主表保留指针 |
| 思考、结构化、工具与输入行为 | [Reasoning](reasoning.md)、[结构化输出](structured-output.md)、[工具协议](tools-and-server-tools.md)、[协议差异](protocol-differences.md)；[模型矩阵](model-capability-matrix.md) 摘要 |
| 原始 usage、错误与观测 | [错误与观测](errors-probing-observability.md) |
| 规范化用量和成本核算 | [核算入口](../../ai-usage-accounting/SKILL.md) |
| 现象型故障 | [故障索引](pitfalls.md)，保留问题编号，原因指回正文 |
| 配置结构与迁移 | [配置入口](../../llm-provider-config/SKILL.md) |
| 协议分层设计与接入流程 | [分层](provider-layering.md)、[接入路线图](migration-roadmap.md) |


三条补充规则：

- **一条事实常常同时命中两层**（例：`[Pro]` 丢 `text.format` 既是平台行为也是模型 × 平台行为）。正文只写一处（选最靠近原因的：转换层 / 渠道行为 → [platform-matrix](platform-matrix.md) §3 该渠道节；模型自身行为 → [reasoning](reasoning.md)/[structured-output](structured-output.md)/[tools-and-server-tools](tools-and-server-tools.md)），矩阵两张表各一格，都指回同一处正文。
- **新平台**：[platform-matrix](platform-matrix.md) §2 加一行 + §3 加一节（节首写「正文所在」行）→ [provider-layering](provider-layering.md) §9 加数据行样例（可选，只在它有新的分层教训时）→ 逐个模型进 22 → 有媒体面进 23。
- **新模型（老平台）**：22 该家族节加行；若家族不存在，新建节（含「家族固有特性」列表，第一版只写文档口径 📄 + 已测的平台行）。

## 4 写法与模板

### 4.1 正文条目（主题篇）

```
**<一句话结论>**（<平台·渠道>，<面>，<模型>，【实测 YYYY-MM-DD】<样本量>）。
发 `<字段>: <值>` → <状态码>，<回包 / 回显关键字段>。
不这样会怎样：<静默后果或账单后果>。
对策：<代码侧 / 数据侧各一句>。
```

例：

> **`[Pro]` 档整个丢 `text.format`**（New API · `[Pro]`，②，gpt-5.6-sol，【实测 2026-09-24】省略 strict 4/4、显式 strict 4/4）。发 `text.format:{type:"json_schema",…}` → 200，回显 `{type:"text"}`，答案仍是合法 JSON。不这样会怎样：能解析的 JSON 让调用方以为 schema 生效，字段缺失 / 枚举越界要到下游才炸。对策：画像格 `structuredOutput` 只对该上游写 `false`；代码侧不加中转站分支。

### 4.2 矩阵格子

格式：`<记号> <关键值>（<补充>）`，每格只写记号 + 关键值 + 证据 + 指针，原因与报文在正文；装不下就写结论 + 指针。

- 思考控制格：`✅ 真分档（low 295 / xhigh 588 tok）；none 🔇 回显 medium`
- 服务端工具格：逐个工具，`web_search ✅ 真搜 6–10 s；code_interpreter ❌ 400；image_generation ❌ 403`
- 静默失败要点格：只写 🔇 与 🔀 的，会响的不写这里

### 4.3 待核实条目（[open-questions](open-questions.md)）

```
| OQ-NNN | P? | 平台 | 面 | 模型 | 待核实：发 <什么>，看 <什么字段> | 现状：库里写「…」，证据【…】 | 相关篇章 | 来源 |
```

### 4.4 坑条目（[pitfalls](pitfalls.md)）

沿用 [pitfalls](pitfalls.md)现有格式：编号、现象、原因、对策、详见。编号只增不改。

## 5 修正旧结论

1. 为新增或本次修改的事实分配稳定 ID（如 `FACT-<主题>-NNN`），检查重复。矩阵引用同一 ID，不复制报文正文；现有坑编号与 OQ 编号保持稳定。
2. 正文与矩阵呈现当前结论，保留观测范围、证据日期和来源定位（官方 URL、源码版本及路径或脱敏日志位置）。缺少原始证据位置时明确写“来源待补”，不得虚构。
3. 被推翻的旧结论移入 [结论历史](conclusion-history.md)，写旧结论、替代原因、证据日期与当前正文链接。历史不参与当前能力判定。
4. 同步相关矩阵和待核实项。样本扩展只追加样本范围；笔误和失效链接直接修正。

## 6 过期与复核

- 按内容变化速度设置复核窗口：价格、配额、模型可用性使用前查当前来源；网关行为与模型能力默认 90 天复核；稳定协议规则默认 180 天或版本变更时复核。窗口是维护策略，可随证据调整，不是厂商事实。
- 复核期限按当前日期动态计算，不写死某次整理的截止日期。已知模型升级、网关换路或文档冲突会提前触发复核。
- 日期或来源缺失时标记待核实。过期不等于错误，也不抹去当时的观测。
- 不因文件迁移或编辑而刷新事实的验证日期。只有实际复核后更新证据与样本。
- 复核后更新当前结论；若推翻旧结论按上一节归档，下线记录同样保留历史。

## 7 证据等级怎么定

| 你手里有的 | 记法 | 能不能据此判错 |
| --- | --- | --- |
| 自己发的请求 + 看到的响应（含日志） | 【实测 YYYY-MM-DD】 | 仅限观测组合、样本和适用时间；推及其他范围需验证 |
| 官方文档 / API 参考页 | 【文档 YYYY-MM】 | 可用于契约一致性判断；与实测冲突时并列记录，不将一次观测推广为通用规则 |
| 读中转站 / 网关源码 | 【中继源码】 | 只对那一类中转站能 |
| 某项目代码在真实服务上跑过，本库没独立复核报文 | 【实现】 | 不能；当线索 |
| 推断、类比、文档含糊、用户口述 | ⚠ / 【未验】 | 不能 |

降级规则：经翻译层网关看到的官方行为 → 最高只能记「【实测 YYYY-MM-DD 经 X】」，且只有回包原样的面才能记为官方事实；请求被重新序列化的网关上「发非法值 200」不能推出官方也 200。

不要为了显得完整而升级证据。宁可一格 `—`，不要一格 📄 冒充 ✅。

## 8 写回自检清单

每次写回前逐条过：

- [ ] 七字段齐全（§1）：主键、发了什么、看到什么、记号、后果、证据 + 日期 + 样本量、出处。
- [ ] 正文只写了一处；矩阵格都指回这一处。
- [ ] 写回前 grep 过该主键（模型 id、平台名、字段名），没有另起重复条目；有旧条目的走 §5。
- [ ] 主键是 (平台·渠道·线路, 面, 模型)，中转站没有把渠道漏掉；同一台至少两个渠道都测了才归转换层（[provider-layering](provider-layering.md) §9.2 第 2 条）。
- [ ] 记号用对：收下 200 但不生效是 🔇 不是 ✅；文档口径是 📄 不是 ✅。
- [ ] 数值、字段名、状态码、报错原文都在；没有「支持 X」这种空话。
- [ ] 静默的后果写了「不这样会怎样」。
- [ ] 新平台：[platform-matrix](platform-matrix.md) 加行加节；新模型：[model-capability-matrix](model-capability-matrix.md) 加行；新媒体面：[media-matrix](../../ai-media-api-integration/references/media-matrix.md) 加行；新现象：11 加编号（表格一行，原因写在正文篇）。
- [ ] 当前结论与历史分离；历史保留证据和当前正文链接。
- [ ] 按内容类型与当前日期计算复核状态，过期或来源缺失的进入待核实表。
- [ ] 表格单元格内没有 `|`、没有换行。
- [ ] CHANGELOG.md 加一行：日期、入口类型、改了哪些文件、一句话。

## 9 三个吸收样例

**样例一：新平台（假设「某某云」，只有 ① 面，测了 3 个模型）**

1. [platform-matrix](platform-matrix.md) §2 加一行（面、base 与鉴权、目录形态、手脚、计费）；§3 加一节，逐条写：透传证据（回包是原样还是翻译层）、非法参数报法、注入读数、`/models` 可信度。
2. 22 各家族节按 (某某云, ①, 模型) 加行；服务端工具有的话 §[video-generation](../../ai-media-api-integration/references/video-generation.md) 加行。
3. 若它教了新的分层教训（例：又一种「同一 id 多渠道」），[provider-layering](provider-layering.md) §9 加数据行样例；否则不加。
4. 没测的面（②③④）不写 ❌，写 `—`；想测但没 key 的进 31 P1。
5. CHANGELOG 一行。

**样例二：新模型（假设 Claude Opus 6，经 OrcaRouter ④ 原样测）**

1. [model-capability-matrix](model-capability-matrix.md) §4 Claude：「家族固有特性」只改跨平台成立的（如新代次的 thinking 方言）；平台表加一行 (OrcaRouter ④, Opus 6)。
2. [reasoning](reasoning.md) §2 / §3 正文：新方言或新档位写在对应小节，标「经 OrcaRouter 原样，【实测 YYYY-MM-DD】」。
3. 官方直连未测 → [model-capability-matrix](model-capability-matrix.md) 该行「平台」列写「Anthropic 官方 · 经 OrcaRouter ④（回包原样）」，不写成「Anthropic 官方」。
4. 目录上限从网关目录抄的 → 标「网关目录，推断」（[provider-layering](provider-layering.md) §9.5）。

**样例三：推翻旧结论（假设复测发现 `[Pro]` 又开始执行 `text.format`）**

1. 假设后续实测显示执行：正文更新为该次观测的当前结论，保留组合、日期与样本；旧判断移入结论历史，不将假设样例写成已发生的实测。
2. [model-capability-matrix](model-capability-matrix.md) §3 GPT 表更新简明结论，链接正文与历史。
3. [platform-matrix](platform-matrix.md) §3 `[Pro]` 节的静默行为列表：该条改写并注日期。
4. [platform-matrix](platform-matrix.md) §3 New API 节「正文所在」行证据日期更新。
5. 31：若之前有「`[Pro]` 是否稳定丢 format」的 OQ → 删；新增「账号池同一档位是否随账号变化」的 OQ（若还没有）。
6. [pitfalls](pitfalls.md)坑 160 不改编号，条目正文加一句「2026-11-02 复测已不复现，见 [structured-output](structured-output.md) §5.1」。
