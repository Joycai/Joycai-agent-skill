# 06 已踩过的坑

每条：症状 → 原因 → 做法。前四条是实施后的代码评审发现的。

1. **改了主线路，一批模型悄悄换了协议，请求被拒。**
   没显式选线路的模型跟随主线路，带着按旧协议族设置的参数。→ 改主线路前，先把这些模型显式钉在旧主线路上。

2. **平台默认路径更新后，旧渠道的路径被冻结在旧值。**
   「旧版本回写」的判断只比较「按今天规则算出的地址」与扁平字段，约定一变就误判为回写。→ 写入时在主线路记下写进扁平字段的值，读取时与它比较。

3. **兼容线路指向厂商主机，保存后地址损坏。**
   「是否官方」按平台推断（厂商主机 → 官方平台 → 官方线路 → 清空主机）。→ 按线路自身的「是否官方」判断。

4. **打开设置页连续弹出多个密钥授权框。**
   为检测可合并渠道读取了全部凭据。→ 只读平台与主机都与其他渠道相同的那几份。

5. **迁移后请求地址差一个字节（主机大小写、尾斜杠）。**
   用 URL 解析库拆地址。→ 按原始字符串切分；每个旧预设一条逐字节测试。

6. **非某平台的兼容端点收到了那家的私有字段。**
   私有能力按协议标准判断（「兼容 ≈ 某一家」）。→ 按 (平台, 协议族) 查画像；推断不出平台归入「自定义」，没有私有扩展。

7. **一次保存把平台推断冻结，以后的画像更新到不了这条记录。**
   保存时写回了推断结果。→ 只在用户选择与推断不同时才存。

8. **切线路后，目标线路带着旧线路的参数。**
   切换时只写了目标参数里存在的字段；或保存与切换各用一套清字段规则。→ 覆盖清单里的全部字段；保存与切换共用一条规则。

9. **切走再切回，文档输入 / 联网开关没了。**
   切线路时按当前线路清掉了授权。→ 授权属于模型，切线路不清，使用时按线路判断。

10. **关掉一条线路后，某模型的请求悄悄改走了主线路。**
    连接解析失败时回退到主线路。→ 请求侧报「线路不存在」，只有展示侧回退；有模型在用的线路不允许关闭。

11. **合并后，某处设置仍指向已删除的模型。**
    只改了配置记录，没改应用状态、辅助代理绑定、用量记录。→ 按 id 映射一次改全；凭据最后删除。

12. **旧版本导入新备份，线路信息丢了。**
    旧版本没有版本检查，或检查写成「不等于」而不是「大于」。→ 版本检查从第一版就有；新格式版本 +1。

13. **估算显示辅助代理能联网，运行时却不能。**
    估算读原始授权，运行读实际可发出集合；或两边拿到的渠道数据不同。→ 所有对外承诺能力的地方都读实际可发出集合，并共用同一份数据。

14. **同名模型提示误导用户。**
    把带日期后缀的快照版本也算作同名。→ 只去掉「厂商/」前缀并忽略大小写；猜错的提示比没有提示更糟。

15. **趁重构把存储也改了名。**
    存储结构与内部类型跟着界面词改名，改动面巨大却换不来任何行为。→ 只改界面词。

16. **中转站上带作者前缀的模型，失去了目录里的已知事实。**（2026-09-27）
    中转站把上游模型再挂一层前缀（`[分组]gpt-…`、`vendor/…`），全局目录按原始 id 查不到，于是上限、严格 schema 名单、有无推理都落空。
    → 只在中转平台上算一个**规范化 id**：按渠道前缀表**最长匹配**去作者前缀，没命中则去开头的 `[…]`，再去 `vendor/`；它**只用于查全局目录**。
    平台格（画像里按模型名的闸门）与上游格仍按**原始 id** 匹配——平台格描述的是这个平台自己供应的 id，对规范化 id 匹配会让平台不供应的写法命中它的行。
    **非中转平台不做**：第一版在所有平台上都去前缀，官方平台上带 `[…]` 的行也开始提档，已收回。
    目录给的上限只进规划、不进请求里的 `max_tokens`。

17. **一个旧字段在每处读取现场解析，每轮评审各找出一个新边界。**
    旧的粗粒度思考方言与新的类目并存，抽屉初值、换线路、改 id 矫正、只读视图、矩阵各自解析一遍。→ 按请求原来的解析方式把行改写一次（02 篇 §3「一次性迁移的例外」），下游不再认识旧字段；库与备份走同一函数。
