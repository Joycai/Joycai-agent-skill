# 05 设置界面

## 1. 八个问题八个视图

| 视图 | 回答的问题 | 要点 |
| --- | --- | --- |
| 总览列表 | 按什么分组？ | 渠道组头 = 平台标签 + 线路标识（只列平台提供的）；组内每个模型行尾一枚写全名的线路标识，一眼看出哪个模型走哪条路 |
| 添加渠道 | 用户先选什么？ | **先选平台，不再选协议。** 旁边预览：会建哪几条线路、每条线路支持哪些私有能力、会预置哪些模型；只需填**一份凭据** |
| 渠道编辑 | 多个协议在哪配？路径怎么改？ | 一张线路表，每族一行：路径 / 鉴权 / 连通测试 / 启用 / 设为主线路；主机只填一次；每行显示实际请求地址 |
| 模型编辑 · 线路切换 | 怎么切一个模型的协议？ | 顶部一条线路条（已配置实线、未配置虚线加号）；下方各分区标注作用域：「模型」与「本线路 · X」 |
| 能力矩阵 | 这个能力在这里能不能用？ | 行 = 能力开关，列 = 线路，格 = 可发出 / 发不出 / 未实测；当前线路列高亮；开了但发不出 = 开关亮 + 「本线路不发」 |
| 切换差异 | 切的时候哪些参数会变？ | 就地展开「旧 → 新」；未配置显示虚线「未设置 · 不发」——**不从旧线路复制** |
| 合并提示 | 重复的渠道怎么收拢？ | 列表顶部提示 → 预览（线路并入、同名合一、引用计数）→ 确认 |
| 同名模型 | 同一模型在不同平台能力不同，用户看得见吗？ | 模型行上「同名 ×N」提示；模型选择器里显示每个模型所走线路 |

## 2. 线路标识：名字，不是编号

- 用简短的等宽标签写协议名：窄处用简写（Chat · Resp · Gemini · Anth），宽处用全名（Chat Completions · Responses · Anthropic）。
  **不用 1–4 这类编号**：编号要记、要图例，名字一眼能读。
- 状态只用填充与描边表达：**实底 = 当前 / 有模型在用**，细描边 = 已配置，虚线 = 平台提供但未启用。
- **平台不提供的线路不显示**，不画空位——空位只在编号体系里有意义。
- 专用接口（出图、转写）**不使用协议标识**，改用一行文字说明（「出图 · 异步任务」）。

## 3. 渠道编辑：线路表与路径

- 路径输入：
  - 缺省：空输入框 + 占位文字显示默认值 + 「默认 /v1」虚线标签，「恢复默认」不可点；
  - 已覆盖：实线框 + 「已改 · 默认 /v1」；
  - 绝对地址：主机位显示「独立主机」。
- 标签与「恢复默认」放在输入框下方第二行，不和主机、输入框挤在一行。
- 每行下方显示实际请求地址（`POST https://…/chat/completions`），**由协议适配层自己的地址拼接逻辑算出**，界面不另写一份——第二份拼接规则迟早与实际不一致。
- 每条线路可单独测连通；「关闭」对有模型在用的线路与唯一线路不可用，并说明原因。
- 官方线路地址锁定，不显示路径输入。

## 4. 模型编辑

- 线路条放在编辑区顶部；单线路渠道不显示（单线路零负担）。
- 按作用域分区：与协议无关的（名称、价格、上下文窗口、能力授权）标「模型」；随协议变化的（思考、最大输出、温度、结构化）标「本线路 · X」。
- 「将发送的内容」预览按当前线路计算。
- 「测上限」等探测测的是当前线路，结果写回当前线路。

## 5. 用词

- 面向用户的词：「渠道」与「线路」成对使用。若原来叫「供应商」，**一次性全部改名**并登记到术语表——新界面只能说「渠道」，一个东西两个名字比改名更糟。
- 存储与内部命名可以不改（02 篇 §1）。
- 协议族可以在文档里用编号速记，但不进界面。
