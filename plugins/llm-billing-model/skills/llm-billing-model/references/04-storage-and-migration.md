# 04 · 存储与迁移

## 列的可空与默认：语义决定，不是习惯

| 列 | 可空？ | 为什么 |
| --- | --- | --- |
| `fee_groups.cache_input_price` | 可空，无默认 | 空 = 同输入价；`0` = 真免费。迁移时**老组得到空**，不是 0——否则一夜之间缓存全免费 |
| `token_usage.cache_price` | 可空 | 只在缓存价存在之前写的行上为空；读时回退到 `input_price` |
| `token_usage.reported_cost` | 可空，无默认 | 空 = 没报；`0` = 上游说免费 |
| `fee_groups.input_unit_price / input_free_units` | 默认 0 | 0 就是「不收」，多数组的真实状态 |
| `token_usage.output_units …`（规格七列） | `DEFAULT 0.0` 与 NULL 混在库里 | 老行被 ALTER 给了 0，新行写 NULL，**读时二者同义**（全 0/全空 = 无快照） |

**错类型的格读作缺失。** SQLite 把文本存进 REAL 列不报错；一行按模式整体解码，一个手改坏的格不能让整页失败——
包括该行模式根本不读的格。`toInt()` 对无穷抛错，先判有限。

## 迁移只加不改

- 每次改表 = 一个版本号 + `on_upgrade` 一步 + `on_create` 同步加上；`ADD COLUMN IF NOT EXISTS` 幂等，可重复跑。
- 老行不回填价格：它们本来就没被计费（v42 前没有规格快照 → 读作无快照、按当时模式算），回填等于捏造历史。
- 不存可从别的表推出的列。
- 版本号也印进备份文件：新版备份被旧版**整体拒绝**而不是导到一半；导入时先把行滤成本库真有的列（否则新版加一列，旧版导入在那一个键上失败并整事务回滚）。
- 事实：旧版没有「滤列」的那几个发布，对之后每个新列仍是整库归零——治不了已发出去的构建，只能让下一个新列以后好过。

## 局部更新与专属写入口

- **有自己写入口的列永远不被整行 `update` 碰。** `sort_order`（拖拽）、模型的 ETA 三列、用量行的输出四列（结算）——
  仓库层在整行更新里把它们剥掉，编辑器保存它打开时的那一行不会撤销中途落下的重排或结算。
- 视频结算 = `UPDATE token_usage SET 输出四列 WHERE task_id = ?`，返回匹配行数（老行没有持久 id → 0，记日志）。
- 删组：`UPDATE models SET fee_group_id = NULL`、`UPDATE channels SET default_fee_group_id = NULL`；用量行**不动**（它自带价）。
- 合并模型（渠道合并）：`UPDATE token_usage/tasks SET model_pk = 新 WHERE model_pk = 旧`，历史跟着模型走而不是显示「已删除的模型」。

## 读时算钱的代价与检查点

- 每一行读出来都算 `cost`；范围超过阈值（500 行）时每天写一条检查点（总数 + 按组成本 JSON），下次从检查点起累加。
- 检查点的数也来自 `cost(row)`；它是缓存，不是第二套口径。分页（Load More）按时间倒序在 SQL 里做，范围也在 SQL 里做。
- 页面切换范围时带代际号，晚到的旧页丢弃。

## 快照什么、不快照什么

- 快照：单价、数量、单位、规格三元组 + `matched`、发出的张数、计费的张数、报价。
- 不快照：组名、组 id（模型 → 组的关系是当前的，分组统计按**当前**归属；这是有意的——用户重分组后历史跟着走）。
- 快照不含币种：应用一律一种显示币种（`$`）。人民币标价的组要用户自己换算后填——已知问题，见 `06`。
