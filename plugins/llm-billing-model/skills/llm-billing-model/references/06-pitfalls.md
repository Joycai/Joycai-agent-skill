# 06 · 自查清单与已知的坑

## 上线前自查（每条对应一种「记错钱但不报错」）

**算式**
- [ ] `cost(row)` 只有一份；汇总、分组、检查点、导出、明细都调它。
- [ ] 输入与缓存 token 在行上**不重叠**；Anthropic 三桶相加后再减；Google 输出加思考。
- [ ] 缓存价空 → 回退输入价；`0` 保持 0。
- [ ] 档位匹配：空条件匹配一切；最具体赢；同具体先写赢；像素尺寸按面积落档、只在表里有的档之间比；精确尺寸压档位。
- [ ] 请求值、回显值、表里的条件三方都过同一个归一化（`1k → 1K`、`768P → 768p`、`1024*1024 → 1024x1024`、`auto → 空`）。
- [ ] 一张没交付 → 输出 0、输入也 0。免费张数按每次请求。
- [ ] 上游报价：空 ≠ 0；有值压过全部；负数 / 非有限 → 当没报；有报价的行不计「未覆盖」。
- [ ] 报价只信平台表里声明过的（实测「报的 = 实扣」），且请求地址也指向该平台；被标错的中转不发头、不收数。
- [ ] 几次请求记一行：全报才加，缺一次整行 null；零次是 null 不是 0。
- [ ] 显示的钱（草稿卡、会话累计）与记的钱走同一个 `cost()`、都接报价；报价参数在写入口与显示函数上必填。
- [ ] Google 的 `toolUsePromptTokenCount` 加进输入；按条收费的服务端工具（Google 搜索）在无报价的平台上会少算，开关旁写明。

**记账**
- [ ] 三条路径进同一入口；`price_spec` 是纯函数，三条各一条测试。
- [ ] 记账在取消 / 内容拦截 / 入会话之前；永不抛错；失败 WARN。
- [ ] 按 token 渠道没回 usage：记 0 + 每次调用警告一次；`prompt_tokens_of` 对「没回」返回空不是 0。
- [ ] 按规格组带图就记，没 usage 也记。
- [ ] 每个图片块带 `input_image_count` 与 `reported_cost_usd`；回报的 0 明发。
- [ ] 视频：提交即记、id 持久、结算只写输出四列、失败 WARN 不影响视频。
- [ ] 每处原样铺上游 map 都走 `upstream_usage`（剔两个保留键），每处一条伪造用例；中转协议不翻报价。
- [ ] 每个把上游 body 整个当信封返回的轮询（异步作业面）返回前剔两个保留键，各一条伪造用例——「找 spread」查不到这一类。
- [ ] 新协议：带参考图就发张数（否则输入费静默记 0）；vendor 自己的用量块嵌子键。
- [ ] 网关报价：每个协议面分别测「带不带头」「流里在哪一块」，只读收尾那块（Anthropic 的 `message_start` 是半截）。

**存储**
- [ ] 可空列的语义写在迁移注释里；老行得到的是「空」而不是 0（缓存价、报价）。
- [ ] 错类型格读作缺失；无穷不 `toInt()`。
- [ ] `on_upgrade` 与 `on_create` 同步；幂等。
- [ ] 有专属写入口的列在整行更新里剥掉（排序、结算的输出四列）。
- [ ] 备份带版本号，新版文件被整体拒绝；导入先滤列。
- [ ] 删组置空引用不删行；合并模型改写 `model_pk`。

**界面**
- [ ] 不收的费不出现（输入图、缓存 0）；没配的组不占位。
- [ ] 未覆盖提示只数 `matched = false` 且无报价的行；「去补档位」直达。
- [ ] 成本 0 用 outline；报价行无标记；估算永不隐藏；退色的一对是唯一信号。
- [ ] 日合计只在整天在范围内时显示。
- [ ] 三档宽度截图 + 溢出断言。

## 需要真实 key 才能定论的（写进台账，带日期）

| 条 | 怎么看 | 为什么静默 |
| --- | --- | --- |
| 按面积归档与该家实际计价是否一致 | 对照账单：1696×960 按 1K？1536×1536 按哪档？ | 归错档只记错钱 |
| 「首张免费」是按每次请求还是按账期 | 两次各带 1 张的请求，账单输入费是否为 0 | 按请求免会少记 |
| 失败 / 被审核拦下的请求是否仍收输入费 | 对照账单（应用记不到：失败根本走不到记账） | 少记 |
| `n>1` 时输入图收一次还是乘张数 | 发 `n:2` 读回包金额 | **已测（xAI）：收一次** |
| 网关回包报价是否等于网关账单 | 同一请求读回包的报价与 `GET /v1/generation` 的 `total_cost` | **已测（OrcaRouter）：④③ 相等，①② 差不到一个 1/500,000 美元单位** |

## 已知没做的

- 计费组币种：一律 `$`；人民币标价的组要用户换算后填。
- 按 token 模式的图像输入单价（gpt-image 图 $8/M vs 文本 $5/M）：差额小，未立项；`input_tokens_details.image_tokens` 在回包里。
- 聊天面（①③④）不发布 `input_image_count`：中转把按张收输入费的模型挂在聊天面上又配按规格组 → 输入费静默 0，无真实用例。
- 视频的输入图：四家文档都没写首帧 / 参考图是否单独计费；没有视频协议发布张数；两处得一起开。
- 组级「信任上游报价」开关：信任改由平台声明（零配置即生效）；把直连 vendor 指到原样转发 `usage` 的中转时报的是供应商收中转的价，接受、不加开关。
- 翻译 / 出图 / 转写这类不走对话协议的子任务：不接网关报价，写入口上显式传 null，照表算。

## 做过又推翻的

- **把价格存在模型上、算钱时查当前价** → 改一次价历史全变。改成组 + 行快照。
- **规格快照塞进一个 JSON 列** → 视频结算整列重写会抹掉输入三列。输入侧独立成列。
- **用 `DEFAULT 0` 加缓存价列** → 老组一夜免费。改可空 + 读时回退。
- **只让单位为「张」的组收输入费（"没有视频协议发布张数"）** → xAI 视频实测参考图另收 $0.01/张，按秒的组一分不记。改成视频提交返回张数、判据不看单位。
- **视频报价按提交回包找** → xAI 的 `cost_in_usd_ticks` 只在终态轮询里；提交与 202 都没有。结算加第二段写报价列。
- **只在 xAI 协议剔保留键** → 聊天四族与流式面同样原样铺 `usage`，仍可伪造。改成一个 `upstream_usage` 处处走。
- **报价只放在收尾块** → 流在出图后被放弃就退回档位表。图片块也带。
- **分辨率档位写每家的边界表** → 改成按面积对数最近、只在表里有的档之间比。
- **回包里有 `usage.cost` 就收** → OpenRouter 形态的中转在 Chat 上本来就回这个字段，一个没测过的数压掉整张表。改成平台声明信任 + 地址相符。
- **只凭平台标签信任** → 作者先选平台再改地址，标签不跟着变；贴错标签的中转照样定账。加上「地址也指向它」这道门。
- **多轮报价直接相加** → 有一轮没报就被当成免费。改成全报才加、缺一次整行回落到表。
- **报价从 `message_start` 起就读、没报就保留旧值** → 开场快照的数是半截的，流在 `message_delta` 前断掉时半截数被当成整段报价。改成只读收尾那块、直接赋值。
- **用源码扫描钉「每个记账调用都传了报价」** → 看不见先在别处组好的参数对象，删掉一处照样全绿。改成写入口类型上必填（没有就明写 null），漏传是编译错误。
- **按 token 算 Google 的用量只读 `promptTokenCount`** → 读网页、代码执行的回填在 `toolUsePromptTokenCount` 里，另算。加进输入。
