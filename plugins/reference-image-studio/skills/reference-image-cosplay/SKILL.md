# 从角色参考到真实 cosplay 服装展示

将动漫游戏角色的设计转译为看起来可实际穿戴、具有真实材料质感的人台展示图，包含服装、假发和配饰。保留原设计的识别特征，清楚展示部件与层次；不默认交付纸样、尺寸规格或生产工艺图，也不宣称仅凭效果图验证了可制作性。

## 参考审查

先读工作区已有的 `AGENTS.md`、`REFERENCE_WORKSPACE.md`（如有）、`references/INDEX.md` 及相关设定，实际查看本次全部相关参考原图。支持单张全身图、多视图、局部特写和文字补充，不强制交齐三视图。尚无索引时直接使用用户本次提供的材料；需要视觉转换但没有可查看的参考时，先请求角色参考，不凭角色名声称已审查原设定。

沿用已有目录，不以初始化为前提。用户要求初始化或维护参考时，使用同插件 [reference-image-workspace](../reference-image-workspace/SKILL.md)。只读取与本次对象相关的材料，不从其他项目继承角色设定。

按部位建立来源映射，记录图片编号或路径、视角、造型版本、穿戴状态及适用范围。全身图约束整体，特写补充局部，材料类比只约束质感；不同皮肤、变身或拆除配件状态不能无声混用。用户最新明确纠正约束对应部位；来源冲突不能靠文件新旧或模型偏好裁决。

审查以下内容：

- 轮廓、比例、配色分区、长短关系和左右不对称设计。
- 实际存在的服装、鞋袜、假发、饰品；逐项记录位置、数量、方向和标志性形状。
- 独立与连接关系、穿戴顺序、覆盖与露出范围；区分衣服开口、肤色面料和人台露出。
- 假发的发色分区、刘海、长度、卷度、主要发束及体积；配饰如何与假发共存。
- 未展示的背面、模糊纹样、被遮挡内层、冲突细节和无法确定的固定方式。

每项判断区分“参考中可见”“用户明确设定”“拟采用的转译方案”“待确认”。高光不能证明材料是乳胶，暗线不能证明存在接缝，外部轮廓不能证明隐藏裁片或闭合方式。未显示的配件不自动视为不存在；不要因遮挡将连体内搭擅自改成上下分体。

## 真实材质与结构转译

保持设计的轮廓、配色、部件位置、数量和层次，再提出真实化选择。不要为了写实擅自简化花纹、缩小标志性装饰、增加覆盖或改变款式；必要改动应作为方案列出。

- 材质写出光泽、厚薄、挺度、垂坠、表面纹理和边缘处理，而不只使用“高级”“真实”等词。材料未指定时，给出适合该部件形态的推荐表现；不能把推荐写成原作事实。
- 区分绘画高光、阴影和实体结构；在中性棚拍光线下保留设计色，不机械复制原画光照或发光效果。
- 布料表现合理厚度、张力与褶皱；金属、树脂、透明件等以体积、边缘和反射区分，避免所有部件变成同一种塑料表面。
- 夸张蝴蝶结、挺立裙摆、悬浮装饰、大体积发束可提出内衬、支撑或隐藏固定方案。会改变可见外观或结构的方案须纳入确认；不虚构原作的隐藏工艺。
- 假发保留角色发型的主要形状，以纤维、发束与造型表现落地，避免真人自然头发或塑料头盔质感。
- 同一部件在正侧背、特写和分层图中使用同一结构与材质定义。易误导的类别名称用轮廓、连接、覆盖和边缘形态补充说明。

## 方案与确认

建立 `generations/<唯一批次>/`，或沿用工作区的生成输出目录，保存带版本号和状态的 `PLAN.md`。第一次回应先提供可评审的整体方案，不只给任务步骤或问题列表。方案包括：

1. 本次造型版本、整体还原方向和必须保留的识别特征。
2. 部件表：来源与确认程度、结构和层次、建议材质表现、必要的现实化选择。
3. 出图清单：按 [展示模板](references/display-template.md) 明确主视图、侧面选择、特写部位、分页及可选分层范围。拟定出图清单前读取该模板。
4. 影响结果的疑问及建议选项。优先询问背面缺失、版本冲突、连接关系、内层结构等关键问题；背景、人台颜色等低影响选项给出默认方案即可。
5. 缺乏直接参考的补全部位与拟采用的设计。用户可补图、文字说明、选择建议，或授权按所列方案推断；不无限索要不存在的参考。

用稳定编号标识疑问和方案项，方便用户局部调整。补充参考后重新查看相关图片，更新受影响项并展示当前有效方案；不把新参考无声加入已确认版本。

默认等待用户确认方案并解决关键疑问后再调用图像生成或编辑工具，不用“试图”“预览”绕过确认。可以继续整理材料和准备提示词。请求确认时说明这是本 skill 约定的“先审查并确认方案，再生成”流程。

“按这个方案开始”或“第 2 项改成……然后生成”即为相应范围的授权，不重复询问。仅补图、回答一个疑问或确认一条设定，不代表批准全部方案；沉默也不是批准。在 `PLAN.md` 记录获批版本、范围、允许的推断和用户确认内容，后续恢复时沿用授权。用户明确要求跳过确认直接生成时遵从并记录，但不将未知结构写成事实；关键缺口无法据授权处理时仍需明确指出。

## 生成与核对

1. 读取获批方案，保存实际提示词和参考职责映射。提示词明确这是同一套真实 cosplay 服装的人台棚拍展示，区分完整穿戴、局部特写和移除指定外层的状态。
2. 使用环境已有的图像能力，遵守其工具规范，有适用的图像工具 skill 时读取必要说明。不绑定供应商、密钥或本机路径。实际传入相关原图，不能把提示词里的路径当作已传图；输入数量受限时优先本视图最相关依据并记录遗漏，关键依据无法传入时说明限制。
3. 多次生成共用获批部件与材质表。已生成视图可作外观一致性辅助，但不能替代原始参考或传播其中的错误。保持稳定部件编号与穿戴者左右定义。
4. 输出为独立版本，保留原件，按视图或展示板命名。工具仅返回引用时保存可用引用，不编造本地文件；无法出图时交付准备材料并明确图片尚未生成。
5. 实际查看整图和关键细节，核对：三视图是否属于同一套服装；配饰是否遗漏、重复、镜像或移位；纹样、连接、层次及材质是否一致；特写能否对应主图；分层图是否保留完整造型中已露出的内层设计。另查部件悬浮、布料穿插、假发穿过饰品、错误人台部位以及裁掉鞋帽、裙摆或垂饰。
6. 已批准范围内的质量纠偏直接执行，不重复确认。需要新设计决定或新增输出范围时提交具体变更。连续两次修正仍出现同类错误时停止重试，保留最接近版本并报告偏差；用户指定的次数或预算优先。后续独立成图修复可交给 [reference-image-repair](../reference-image-repair/SKILL.md)。
7. 交付实际图片预览或文件链接，简述完成的视图、主要材质选择、获准的推断与剩余偏差，不将提示词冒充图片，不声称未目视检查的结果已通过核对。

批次 `NOTES.md` 记录参考来源、获批方案、实际图像输入及职责、提示词位置、输出版本、目视核对和待确认事项。生成结果保持“待用户核对”；只有用户要求维护参考且明确认可相应内容时，才按认可范围更新共享索引。将角色原设定与本次 cosplay 材质、支撑和结构方案分开记录，不让一次真实化选择改写原作设定。
