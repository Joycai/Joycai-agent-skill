# 可信参考驱动的图片生成

用文字或草图决定本次画面，用仓库中有明确来源和适用范围的知识与样本保持设计一致性。支持动漫角色及其他对象，不预置角色设定，不把“文件在仓库里”当作可信依据。

## 仓库与依据

先读当前工作区已有的 `AGENTS.md`、`REFERENCE_WORKSPACE.md`（如有）、`references/INDEX.md` 及索引指向的相关设定，再实际查看本次涉及的参考原图。沿用仓库已有组织方式；不要为了使用本 skill 重排素材。若用户要求初始化，使用同插件 [reference-image-workspace](../reference-image-workspace/SKILL.md) 的初始化与参考维护流程，三个 skill 共用参考索引；不需要待修成图也可以初始化。仅缺少索引时可直接使用用户本次明确提供的设定和参考，不以初始化或创建索引作为出图前置条件；写入共享索引须有用户维护参考的意图。

按部位和问题选择依据，而不是给全部图片排一个通用优先级：

- 用户最新明确确认的设定与参考用途约束相应部位；可信标准图、被确认的样本只在其适用范围内有效。
- 设定文档须能追溯到用户确认或原始样本。草稿笔记、猜测、旧提示词、生成结果和弃用示意不自动可信；文件名、更新时间或“看起来合理”不能替代来源。
- 完整造型、变身阶段、拆除配件图、动态样本和跨对象类比分别使用。某状态中未显示的部件，不代表标准造型没有该部件。
- 不照搬参考的姿势、光照或画面布局；参考只用于其声明的职责。按新画面的透视、缩短、受压、动作和遮挡调整可见形状。
- 未展示的接缝、裁片和闭合方式保持未知。画面必须显示但缺乏依据的关键身份或结构细节，先针对该问题询问；背景等非关键创作空间可合理发挥并在记录中区分，不将发挥写回标准。
- 用户明确要求新的变体时，按本次要求生成并标为变体，不擅自更新常规设定。若新描述与标准冲突且无法确定是否为有意变体，只核实影响结果的冲突。

## 文字输入

提取主体、动作、表情、镜头、构图、场景、风格及用户明确指定的尺寸或透明要求。未指定而不影响身份一致性的细节可自行选择，不为每个创作选项反复提问。用仓库可信设定补全角色与道具设计；已有相关图像样本时，应将其实际提供给生成工具，不能仅靠文字记忆复现。可信依据仅有文字且足够明确时，可以直接按文字生成，不强制索要图片。

若仓库缺少可信材料，先完成可做的材料整理，并请求最关键的参考或设定；不得将无依据的自由创作宣称为符合仓库标准。

## 草图输入

实际查看草图，区分姿势线、轮廓、标注、箭头和未画完区域。默认保留草图的主体布局、镜头、动作和表情意图，依据可信标准补全身份、服装与道具细节；粗糙线条、简化比例、缺失配饰不是新的设定。用户要求保留线稿、比例、配色或特定形变时遵从其要求。

明确草图是构图输入，标准图是设计依据，不能让工具把参考图的站姿替换草图动作。草图与设定存在重要冲突时区分有意改款和绘制简略；关键意图确实无法判断才询问。标注通常不进入成图，用户要求保留文字或示意箭头时例外。保留草图原件，不覆盖它。

## 生成与核对

1. 建立 `generations/<唯一批次>/`（或遵循仓库已有生成输出目录）。保存用户要求、可获取的草图副本，以及 `NOTES.md` 和实际提示词 `prompt.txt`。登记可信来源路径、适用部位、用户确认信息、创作选择和未确认事项。
2. 将输入分工写清楚：本次文字意图、草图构图约束、每张标准图的适用部位、必须保持的设计、允许发挥的场景。易误导的服装类别名称改写成轮廓、体积、连接或分离、覆盖与边缘形态。只加入与本画面相关的纠偏约束。
3. 使用当前环境可用的图像生成/编辑能力，遵守该工具规范；有适用的图像工具 skill 时读取必要说明。草图成图可使用图像编辑路径；文字生成也可使用图像参考输入。确认工具实际收到了相关图像，并记录图像输入与职责的对应关系，不能把提示词中的文件路径当作已传图。若输入数量受限，优先保留草图与最相关标准，记录遗漏和限制，不谎称全部参考已输入。
4. 按用户要求处理比例与透明背景，不绑定供应商、模型、密钥或本机路径。工具不可用或无法接收必要输入时，保存准备好的提示词和材料清单，说明未完成生成；不要把提供提示词当作已交付图片。
5. 输出保存为独立版本，实际查看整图和关键细节：既核对文字/草图的构图意图，也核对可信设定、部件位置、层次、比例、手部和遮挡，检查是否混入参考背景或跨对象的无关设计。检查结论与用户认可分开记录。工具只返回结果引用时，保存可用引用并说明限制，不编造本地文件或未经目视检查的结论。
6. 有明确偏差时，在本次已授权的构图和设计要求内针对性修正，无需为完成原请求重复索取确认。用户要求独立的成图修复任务时，可转入同插件修正 skill；新增部位、改变构图或引入影响结果的新设定超出原请求时，先确认变更。连续两次修正仍出现同类错误时停止重试，保留最接近的版本并说明具体偏差或缺失依据；用户指定的次数或预算优先。
7. 交付真实输出预览或文件链接，简述采用的构图、主要依据及仍有的偏差。生成结果维持“待用户核对”，用户明确认可某部位时才按该范围更新索引，不由模型自检将整图升级为标准。
