# 参考工作区与知识维护

负责 reference-image-studio 插件的共享知识。修图使用 [reference-image-repair](../reference-image-repair/SKILL.md)，从文字或草图生成图片使用 [reference-image-generate](../reference-image-generate/SKILL.md)。

## 初始化工作区

用户要求初始化时，使用本 skill 的 `scripts/init_workspace.py`，向用户指定的工作区写入模板：

```text
python3 "<skill目录>/scripts/init_workspace.py" "<工作区路径>"
```

脚本创建标准目录与缺少的规则/索引，初始化 `.studio/project.json` 并构建 `dashboard/index.html`。登记表和原件不覆盖；Dashboard 页面与缩略图是可重建产物。已有 `AGENTS.md` 时，规则写入 `REFERENCE_WORKSPACE.md`；阅读两者后，将适用的参考工作区规则合并进现有约定或添加链接，保留其他项目规则。重复运行不重复添加规则。

初始化不需要用户先交齐图片。缺少材料时完成目录与规则，再明确告知下一步需要哪些参考图片或文字设定；无需提供待修图片。不要扫描或复制无关工作区的素材；不自动继承本 skill 来源项目的角色、编号和设定。

## 收录与维护参考

- 先阅读工作区已有的 `AGENTS.md`、`REFERENCE_WORKSPACE.md`（如有）和 `references/INDEX.md`。开始图像分析或修正前，实际查看相关原图，不能仅凭索引或会话记忆判断细节。
- 收录用户指定的参考，保持原文件内容不变；保留稳定编号，新增参考接续编号。裁剪或标注副本另存，记录来源，不代替原件。
- 按部位建立首选与补充参考映射。记录每张图的角度、状态、用途、适用范围和不适用范围。特写、全身、动态、拆除配件、变身中途及跨对象类比的用途不能混用。
- 明确区分：用户确认的设定、图像中实际可见的现象、待确认推断。用户对图的用途和结构的明确说明是设定依据；新的明确纠正替代旧推测，并记录被替代内容。
- 同一形状出现在不同位置时，记录所属部位，避免混淆。部分配件未显示，可能源于遮挡、拆除或阶段变化，不能据此删除完整造型中的配件。
- 当类别名称容易引入错误结构时，改用可见形态描述：轮廓、体积、边缘、叠压、色块、覆盖与露出范围。外观效果不能证明隐藏裁片、接缝或闭合方式。
- 不将生成结果、辅助示意或历史探索自动升级为标准。用户确认某部分可用时，只更新其明确认可的范围；旧版本标记为弃用或仅供追溯。
- 真正影响当前修正、且不能由视角、遮挡、光照或绘画简化解释的冲突，记录并向用户核实；可继续处理不依赖该冲突的部分。

## 文字参考与更新

参考可以是图片、纯文字说明，或两者结合；没有图片时也能建立并维护文字依据。读取相关现有条目后，将新增文字按对象和部位登记，记录来源、用户原意、适用状态及确认程度，不凭空配上图片编号。文字足够明确时无需强制索要图片；涉及视觉判断且已有图片时实际查看原件。

用户明确提供的设定纠正可直接更新，不套用修图的计划确认流程。保持当前有效规则清楚：旧规则标为被替代并记录原因，避免新旧矛盾同时充当有效依据。图片与文字发生影响使用的真实冲突时，区分明确纠正与未解决冲突，不能擅自选一个。

收录新图片前核对来源、用途与是否已有相同素材；保持稳定编号与原文件内容。纯描述补充不要创建虚假的图像文件。大段设定可另存为 references/ 内的描述文档并在 INDEX.md 中链接，短说明可直接入索引。只维护当前请求涉及的知识，不顺带生成或修图。

交付时简述新增或更正的依据、适用范围和仍待确认项，并给出更新文件链接。不要把收录成功说成所有设定已核实。

## Dashboard 与统一记录

使用 [reference-image-dashboard](../reference-image-dashboard/SKILL.md) 的 [仓库结构与记录协议](../reference-image-dashboard/references/workspace-contract.md)。新项目采用 `references/`、`inputs/`、`tasks/<任务>/`、`retained/`、`.studio/`、`dashboard/`；已有 `edits/`、`generations/`、`finals/` 不移动，登记原路径即可。初始化即有空页面，不需要先提供图片。

收录或更改参考时，同步 `.studio/project.json` 的 reference 稳定编号、来源、确认状态与适用范围并 build；仅文字设定也可登记文本路径。用户明确保留结果时登记 retained 及 task/step/output 来源，不把保留自动升级为参考。网页展示与索引应表达同一确认边界，避免只改其中一处。

已有项目接入只根据实际索引、历史记录与用户确认登记，不从文件名推断可信性；缺失历史输入和 prompt 明示未知。未登记的图片仅进入未登记栏。页面是快照，各创作技能在每次产出或失败后 build，用户刷新即可观察。
