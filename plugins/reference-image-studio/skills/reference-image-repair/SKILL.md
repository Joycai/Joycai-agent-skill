# 先确认计划，再修复图片

本 skill 负责已有成图的修复。共享知识由 [reference-image-workspace](../reference-image-workspace/SKILL.md) 维护；文字或草图创作新成图使用 [reference-image-generate](../reference-image-generate/SKILL.md)。

## 分析与计划

先读工作区已有的 AGENTS.md、REFERENCE_WORKSPACE.md（如有）、references/INDEX.md 和相关文字设定，实际查看待修图与对应参考原图。尚无索引时，可使用用户本次明确提供的依据，不强制初始化。纯文字依据明确时可据此分析，不虚构图像证据。按部位使用可信标准，结合目标的透视、姿势、遮挡和光照判断；不能仅靠记忆，也不能把拆除配件、变身阶段或跨对象局部参考当成完整常规设计。

建立 tasks/<唯一任务>/（已有项目可继续使用 edits/<唯一批次>/），保存可获取的原图副本和 PLAN.md。先完成足以评审的计划，再请求确认；不要只给“稍后分析并修复”这样的任务步骤。每个修改项使用稳定编号，写明：

- 位置或部位，以及实际观察到的问题。
- 依据的参考图片或文字条目，以及适用范围；不把未知隐藏结构写成事实。
- 具体怎样改、修改边界与需保留的形态。仅疑似的问题单列为待核实，不自动列入执行范围。

计划还需说明底图版本、整体要保留的构图/姿势/表情/画风/背景，以及真正影响修正的待确认项。向用户展示简洁的修改清单，支持按编号删除、增加或调整；PLAN.md 使用版本号与“待确认”状态保存当前完整计划。此处 plan 是工作流程，不依赖应用是否切换到 Plan mode。

## 确认边界

默认先提交计划，等待用户确认或调整，确认前不调用出图或图像编辑工具，也不以“预览/试修”提前动手。可以继续阅读参考、保存原图和准备提示词。提出确认请求时简短说明：这是本 skill 约定的“先确认修改清单，再修图”流程。

用户说“按这个计划执行”“只做第 1、3 项”或“把第 2 项改成……然后开始”均可作为相应范围的明确授权；不需要再问一遍。仅调整计划而未要求开始时，更新并展示完整清单，继续等待确认。沉默、经过一段时间、确认某条设定正确或最初笼统的“帮我修图”不等于确认后来提出的计划。

确认时在 PLAN.md 记录用户认可的计划版本、条目范围与确认内容。后续对话恢复时读取计划与记录，不因上下文压缩丢失已获授权。执行中发现需要新增部位、改变构图或采用影响结果的新设定时，先提交变更项并确认；已批准范围内的质量纠偏不反复请求确认。用户明确要求本次跳过计划确认直接执行时，遵从该指令并记录这一例外，不擅自推定豁免。

## 执行与核对


1. 读取已确认的 PLAN.md，只执行获批条目。默认保留构图、姿势、表情、视线、画风、背景和未指定区域；用户另有要求时以其要求为准。标记图用于定位，优先使用无标记原图作为编辑底图；只有标记图时如实说明材料限制。
2. 从索引选择相关参考并实际查看。用标准图核对设计，用目标图决定透视、缩短、遮挡、动作和光照。不要照搬参考的二维轮廓、固定色值或全部配饰可见程度。
3. 在本批次保存编辑提示词及记录，提示词必须与批准的条目和边界一致。列出底图、参考路径和各图职责，说明要改什么、要保留什么、不要引入什么；只传入相关参考，避免旧错误示意污染输入。
4. 使用当前环境提供的图像编辑工具，并遵守其调用规范。若环境有适用的图片编辑 skill，读取其必要说明。明确区分目标底图与参考图，确保工具实际接收到所需图像，而非仅在提示词中提及路径。不要把某个供应商、API 密钥或本机绝对路径固化为依赖。工具不可用时保存提示词和材料清单，说明尚未生成，不能声称完成。
5. 输出为独立版本，不覆盖参考或待修原件。保留现有透明背景，除非用户要求改变。若工具不返回可保存文件，保留其可用结果引用并如实说明，不编造本地路径。
6. 实际查看结果，逐项比较指定部位、整体保持程度及新增错误。关注重复/漏画配件、错误连接、遮挡穿帮、手部和肢体、比例、色块，以及无关区域的漂移。生成式编辑不保证像素级保留，未经核实不要作此承诺。
7. 有明确可修复的偏差时在已批准范围内再迭代；连续两次修正仍出现同类漂移，或需要新的设定证据时，停止重试，保留最接近版本并报告具体问题。用户指定的次数或预算优先。交付结果预览或文件链接、简短变更说明和仍有的偏差。

## 最小修正记录

每批次的 `NOTES.md` 记录：目标原图与参考来源、用户要求、实际使用的提示词位置、输出版本、目视检查结果、尚未确认的问题。不能把“已生成”写成“用户已认可”。需要更新已确认设定时交由 reference-image-workspace 维护；单次编辑效果保留在批次记录中。

## 项目 Dashboard 同步

工作区存在 `.studio/project.json` 时，遵循 [Dashboard 记录协议](../reference-image-dashboard/references/workspace-contract.md)：新任务优先 `tasks/<唯一任务>/`，已有项目沿用原批次目录并登记 task.json 路径。计划、每次工具返回（包括失败）和核对完成后，逐次记录实际输入顺序/职责/是否传入、模型参数、实际 prompt、独立输出版本和检查结果，然后运行 dashboard skill 的 `scripts/dashboard.py build <工作区>`。不能只在全部成功后补写一条记录掩盖重试，也不能将目视查阅冒充传图。

用户明确保留时增加 retained 记录并关联 task/step/output；生成结果未获相应用途的明确确认前不进入 confirmed reference。没有登记表时不强制初始化或重排素材；直接完成本次出图与既有日志。Dashboard 不替代本 skill 的授权和核对流程。
